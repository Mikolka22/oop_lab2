# Что изменилось во второй лабораторной

Сравнение с кодом первой лабораторной: раньше менеджер запускал одну линию и ждал её завершения; теперь он создаёт линии по случайному расписанию и обновляет все существующие линии в одном цикле. Ниже указаны номера строк **текущих исходников второй лабораторной**, сами изменения и их влияние на другие файлы.

## 1. AppManager.h — частота и объявление составления расписания

**Строка 4:**

```cpp
class System;
```

Добавлено предварительное объявление: компилятору сообщается, что класс `System` существует. Оно нужно, потому что новый метод `makeTimes` принимает `System&`. Полное определение класса здесь не требуется: метод только объявлен, а его реализация в `AppManager.cpp` уже подключает `System.h`.

**Строка 7:**

```cpp
    int frequency, speed, length;
```

К прежним `speed` и `length` добавлено поле `frequency`. В `AppManager.cpp` оно получает значение из ввода, задаёт количество случайных моментов появления и ограничивает число создаваемых линий в одном секундном расписании. В `Line` это поле не передаётся: отдельная линия управляет своим движением, а частота создания относится к менеджеру.

**Строка 12:**

```cpp
    void makeTimes(System& console, int times[]);
```

Объявлен новый закрытый метод. `console` — ссылка на существующий `System`, через который вызывается генератор случайных чисел. `times[]` обозначает переданный массив: изменения его элементов будут видны в `run`. Метод ничего не возвращает, потому что результат записывается прямо в этот массив. Реализация находится в `AppManager.cpp`, строки 30–44.

## 2. AppManager.cpp — ввод, расписание и общий цикл

### Подключение списка — строка 5

```cpp
#include <list>
```

Подключён контейнер `std::list`. Раньше хватало одной локальной переменной `Line line(...)`; теперь нужно хранить несколько объектов `Line` одновременно. Список используется в строке 95 и сам освобождает память удалённых линий.

### Генерация моментов появления — строки 30–33

```cpp
void AppManager::makeTimes(System& console, int times[]) {
    for (int i = 0; i < frequency; ++i) {
        times[i] = console.random(0, 1000);
    }
```

- **30:** начало реализации метода, объявленного в `AppManager.h:12`.
- **31:** цикл выполняется ровно `frequency` раз. При частоте 3 заполняются только `times[0]`, `times[1]`, `times[2]`.
- **32:** через прежний `System::random` из `System.cpp` выбирается момент от 0 до 1000 мс включительно относительно начала секундного расписания. Это момент появления, а не пауза после предыдущей линии.

Эти числа затем читает цикл создания линий в строках 105–110. Например, значение 400 означает время `second + 400`.

### Сортировка моментов — строки 35–43

```cpp
    for (int i = 1; i < frequency; ++i) {
        int time = times[i];
        int j = i - 1;
        while (j >= 0 && times[j] > time) {
            times[j + 1] = times[j];
            --j;
        }
        times[j + 1] = time;
    }
```

- **35:** берётся очередной элемент, начиная со второго. Первый элемент сам по себе уже упорядочен.
- **36:** его значение временно сохраняется в `time`.
- **37:** `j` указывает на предыдущий элемент.
- **38:** пока слева есть элемент и его значение больше `time`, нужно сдвигать его вправо. Проверка `j >= 0` стоит первой, чтобы не обращаться к элементу с отрицательным индексом.
- **39:** больший элемент сдвигается на одну позицию вправо.
- **40:** проверка продолжается дальше влево.
- **42:** сохранённое значение вставляется на освободившееся место.

Расписание `200, 700, 400` превращается в `200, 400, 700`. Это влияет на строку 105: менеджер смотрит на ближайшее событие `times[next]`, поэтому более ранние события должны находиться в начале массива. Одинаковые значения сохраняются и дают одновременное появление нескольких линий.

### Четвёртый параметр — строки 52–54, 61–62, 74–84

В строках **52–54** текст справки изменён под новый порядок: `частота скорость длина Y|N`.

**Строки 61–62:**

```cpp

        if (frequency == 0) return 1;
```

В диалоговом режиме перед скоростью читается частота. Используется прежний `readNumber`: он уже проверяет диапазон 1–30 и повторяет вопрос при ошибке. Возвращённый ноль здесь означает окончание ввода до получения правильного значения, поэтому `run` прекращает работу.

**Строки 74–78:**

```cpp

        frequency = number(argv[1]);
        speed = number(argv[2]);
        length = number(argv[3]);
        mode = argv[4];
```

- **74:** вместо `argc == 4` проверяется `argc == 5`: имя программы и четыре параметра.
- **75:** `argv[1]` теперь содержит частоту.
- **76–78:** прежние скорость, длина и режим сдвинуты на одну позицию.

В строке **80** сообщение об ошибке также изменено: требуются четыре параметра. В строке **84** к прежней проверке добавлено `frequency == 0`, поэтому неправильная частота в CLI останавливает программу так же, как неправильная скорость или длина.

Влияние на остальные файлы: `main.cpp` по-прежнему передаёт `argc` и `argv` в `run`, поэтому менять его не понадобилось. Проверенные `speed` и `length` позже передаются в конструктор `Line`, а `frequency` используется только менеджером.

### Хранение линий и начало отсчёта — строки 95–99

```cpp

    makeTimes(console, times);
    int next = 0;
```

- **95:** создаётся список всех ещё не закончившихся линий. В первой работе существовала одна линия; теперь каждая новая добавляется в этот список.
- **96:** массив хранит моменты появления. Размер 30 достаточен, потому что частота не превышает 30.
- **97:** составляется первое расписание.
- **98:** `next` — индекс ближайшего ещё не обработанного события.
- **99:** через новый `System::time()` из `System.cpp:65–67` сохраняется начало первой секунды. Тип `unsigned long long` позволяет хранить большое число миллисекунд.

### Создание линий по времени — строки 101–110

```cpp
    while (!console.stop()) {
        unsigned long long now = console.time();
        // При задержке обрабатываем и пропущенные секунды, не теряя линии.
        while (true) {
            while (next < frequency && now >= second + times[next]) {
                int x = console.random(1, console.width - 2);
                int color = 10;
                if (colorful) color = console.random(1, 15);
                lines.emplace_back(x, length, color, speed, second + times[next]);
                ++next;

```

- **101:** один общий цикл работает до Esc. Прежний внутренний цикл ожидания окончания единственной линии удалён.
- **102:** текущее время считывается один раз на проход и затем передаётся всем линиям. Поэтому они обновляются относительно одного момента времени.
- **104:** дополнительный цикл позволяет обработать несколько секунд, если программа задержалась.
- **105:** сначала проверяется, что событие ещё есть, затем — что его время наступило. `while`, а не `if`, создаёт сразу все линии, которым пора появиться, включая события с одинаковым временем.
- **106–108:** случайный столбец и цвет выбираются прежним способом, но теперь для каждого события расписания.
- **109:** `emplace_back` создаёт объект `Line` прямо в конце списка. Первые три аргумента прежние; добавлены скорость и запланированное время рождения.
- **110:** индекс сдвигается, чтобы событие не обработалось повторно.

Строка 109 требует нового конструктора в `Line.h:9` и его реализации в `Line.cpp:4–10`. Передаётся именно `second + times[next]`, а не `now`: если создание задержалось, `Line::step` сможет вычислить, сколько шагов уже должно было произойти.

### Переход к следующей секунде — строки 112–115

```cpp
            if (now < second + 1000) break;
            second += 1000;
            makeTimes(console, times);
            next = 0;
```

- **112:** если текущая секунда ещё идёт, выход только из дополнительного `while (true)`. Обновление существующих линий ниже всё равно выполняется.
- **113:** начало отсчёта сдвигается ровно на 1000 мс. Если бы здесь было `second = now`, задержка каждого прохода смещала бы все последующие расписания.
- **114:** выбираются новые случайные моменты появления.
- **115:** обработка нового массива начинается с первого события.

В каждом секундном расписании создаётся ровно `frequency` линий. Событие 1000 мс заканчивающегося расписания и событие 0 мс следующего могут попасть на один момент. Существующие объекты `Line` при смене секунды сохраняются и продолжают движение.

### Обновление и удаление линий — строки 118–124

```cpp
        for (auto line = lines.begin(); line != lines.end();) {
            if (!line->step(console, now)) {
                line = lines.erase(line);
            } else {
                ++line;
            }
        }
```

- **118:** `line` — итератор, то есть объект для обращения к текущему элементу списка и перехода к следующему. `auto` позволяет компилятору определить его тип. Увеличение вынесено из заголовка цикла, потому что при удалении переход выполняется иначе.
- **119:** `->` вызывает метод объекта, на который указывает итератор. Новый аргумент `now` соответствует объявлению `Line::step` в `Line.h:10`. Метод сам решает, пора ли двигаться.
- **120:** если метод вернул `false`, линия завершилась. `erase` уничтожает её объект, освобождает память элемента списка и возвращает итератор на следующий элемент. Старый итератор после удаления использовать нельзя.
- **122:** если линия ещё существует, выполняется обычный переход к следующей.

Изменение связывает менеджер с новой логикой завершения в `Line.cpp:17–20`. В отличие от первой работы, завершение одной линии больше не останавливает обновление остальных.

### Общая отрисовка — строки 126–131

```cpp
        console.clearFrame();
        for (Line& line : lines) {
            line.show(console);
        }
        console.present();
        console.wait(1);
```

- **126:** очищается будущий кадр в памяти через новый `System::clearFrame`.
- **127:** обходятся все оставшиеся линии. `Line&` означает ссылку: копия объекта не создаётся.
- **128:** новый `Line::show` добавляет видимые символы линии в общий кадр.
- **130:** новый `System::present` переносит изменения кадра в настоящую консоль.
- **131:** вместо прежнего `console.wait(speed)` выполняется общая пауза на 1 мс. Поэтому в `System::wait` изменён смысл аргумента: теперь это миллисекунды, а не скорость.

Раньше длительная пауза задавала скорость единственной линии. Теперь скорость учитывается внутри каждой `Line`, иначе медленная линия задерживала бы весь список. После выхода из цикла строка **133** возвращает 0; список автоматически уничтожает оставшиеся объекты.

## 4. Line.cpp — разделение изменения состояния и вывода

### Конструктор — строки 4, 9–10

Сигнатура в строке **4** приведена в соответствие с `Line.h:9`. После прежних присваиваний добавлены:

```cpp
    speed = lineSpeed;
    start = startTime;
```

Строка **9** сохраняет скорость, полученную от менеджера. Строка **10** сохраняет время рождения. Благодаря отдельному `start` две линии с одинаковой скоростью, созданные в разные моменты, начинают движение независимо.

### Шаг по таймеру — строки 13–25

```cpp
bool Line::step(System& console, unsigned long long now) {
    int dy[7] = {0, 1, 1, 2, 3, 3, 4};
    // Время каждого шага считаем от рождения линии, чтобы не копить задержку.
    while (now >= start + number * 1000ULL / speed) {
        if (number >= length) {
            int old = number - length;
            int y = old / 7 * 5 + dy[old % 7];
            if (y >= console.height) return false;
        }
        ++number;
    }
    return true;
}
```

- **13:** новый `now` получен из `AppManager.cpp:119`. Внутри линии повторно обращаться к часам не требуется.
- **14:** прежний массив вертикальных смещений оставлен для проверки положения хвоста. Горизонтальный массив `dx` больше не нужен в этом методе, потому что вывод перенесён в `show`.
- **16:** рассчитывается запланированное время шага. При скорости 10 это `start`, `start + 100`, `start + 200` и далее. Пока время шага наступило, обновление продолжается. Если цикл задержался, за один вызов обрабатывается несколько шагов.
- **16, `1000ULL`:** число 1000 имеет тип `unsigned long long`, поэтому умножение выполняется в широком целочисленном типе. Деление на `speed` переводит скорость в интервалы миллисекунд. Каждый момент рассчитывается от `start`, поэтому округление не накапливается от шага к шагу.
- **17–19:** прежний расчёт номера и строки уходящего хвоста сохранён.
- **20:** если хвост уже ниже окна, метод возвращает `false`. В ответ менеджер удаляет линию через `lines.erase` в `AppManager.cpp:120`.
- **22:** увеличивается номер следующего символа. Прямой записи в консоль здесь больше нет.
- **24:** `true` означает, что линия ещё существует. Это возможно и без нового шага: если его время пока не наступило, менеджер просто перейдёт к следующей линии.

Из старого `step` удалены создание `Symbol tail` с пробелом и вывод `Symbol head`. Теперь хвост исключается при сборке кадра, а освобождённую клетку обрабатывает `System::present`. Это нужно, чтобы хвост одной линии не затирал символ другой.

### Новый метод show — строки 27–42

```cpp
void Line::show(System& console) {
    // Семь букв ромба: A / B C / D / E F / G.
    int dx[7] = {0, -1, 1, 0, -1, 1, 0};
    int dy[7] = {0, 1, 1, 2, 3, 3, 4};
    int first = number - length;
    if (first < 0) first = 0;

    for (int n = first; n < number; ++n) {
        int y = n / 7 * 5 + dy[n % 7];
        if (y < console.height) {
            char letter = 'A' + n % 26;
            Symbol symbol(x + dx[n % 7], y, letter, color);
            symbol.show(console);
        }
    }
}
```

- **27:** вывод выделен в самостоятельный метод, вызываемый из `AppManager.cpp:128`.
- **29–30:** прежние массивы ромба перенесены из `step`. Сама форма не изменилась.
- **31:** вычисляется номер первого ещё существующего символа. Всё, что было раньше него, уже относится к исчезнувшему хвосту.
- **32:** в начале жизни линии `number` меньше `length`, поэтому отрицательный результат заменяется нулём.
- **34:** в кадр добавляется вся текущая часть линии, а не только новая голова. Например, при `number == 8` и `length == 7` добавляются символы 1–7: `B–H`; символ 0, то есть `A`, уже исключён.
- **35–37:** прежние формулы координат и буквы применяются к номеру `n` каждого оставшегося символа. Координаты прежних букв не сдвигаются.
- **38:** создаётся обычный `Symbol` с прежним конструктором из `Symbol.cpp`.
- **39:** вызывается прежний `Symbol::show`. Сам этот метод не менялся, но вызванный им `System::draw` теперь записывает символ в память кадра.

Повторное добавление оставшихся букв в кадр позволяет восстановить букву одной линии после того, как её перестала закрывать другая. Запись в настоящую консоль выполняется позже, только для изменившихся клеток.

## 6. System.cpp — сборка кадра вместо немедленного вывода

### Инициализация массивов — строки 28–31

```cpp

    oldLetters.assign(width * height, ' ');
    colors.assign(width * height, 0);
    oldColors.assign(width * height, info.wAttributes);
```

- **28:** для каждой клетки окна выделяется элемент и задаётся пробел.
- **29:** предыдущий кадр также заполняется пробелами: непосредственно перед этим прежний код очистил настоящую консоль.
- **30:** цвет пустых клеток будущего кадра устанавливается в 0.
- **31:** цвет предыдущего кадра берётся из `info.wAttributes`, потому что именно этим атрибутом прежний код заполнил консоль при очистке.

`assign(количество, значение)` задаёт размер вектора и заполняет его. Без этих строк новые `draw`, `clearFrame` и `present` обращались бы к ещё не созданным элементам. Метод `start` вызывается менеджером до создания линий, поэтому массивы уже готовы к `Line::show`.

### Изменённый draw — строки 35–40

```cpp
void System::draw(int x, int y, char letter, int color) {
    if (x < 0 || x >= width || y < 0 || y >= height) return;
    int i = y * width + x;
    letters[i] = letter;
    colors[i] = color;
}
```

- **36:** добавлена проверка границ перед обращением к массивам.
- **37:** координаты переводятся в индекс: сначала пропускаются `y` полных строк по `width` клеток, затем `x` клеток текущей строки.
- **38–39:** символ и цвет сохраняются в будущем кадре.

Раньше этот метод сразу вызывал функции Windows. Теперь эти вызовы перенесены в `present`. Объявление `draw` не изменилось, поэтому `Symbol.cpp:11` продолжает вызывать его тем же способом. Изменился результат этого вызова: символ сначала попадает в общий кадр.

Если несколько линий записывают одну клетку, остаётся последняя запись. Менеджер обходит список от старых линий к новым, поэтому при пересечении виден символ более новой линии.

### Новый clearFrame — строки 42–47

```cpp
void System::clearFrame() {
    for (int i = 0; i < width * height; ++i) {
        letters[i] = ' ';
        colors[i] = 0;
    }
}
```

- **43:** обходятся все клетки будущего кадра.
- **44–45:** будущая клетка становится пустой и получает цвет 0.

Векторы `oldLetters` и `oldColors` сохраняются. Настоящая консоль здесь тоже не очищается. После этого вызова менеджер заново добавляет все существующие линии через `Line::show`; клетки исчезнувших хвостов остаются пустыми, если на них нет другой линии.

### Новый present — строки 49–63

```cpp
void System::present() {
    HANDLE console = GetStdHandle(STD_OUTPUT_HANDLE);
    for (int i = 0; i < width * height; ++i) {
        if (letters[i] == oldLetters[i] && colors[i] == oldColors[i]) continue;
        COORD pos;
        pos.X = left + i % width;
        pos.Y = top + i / width;
        WORD attribute = colors[i];
        DWORD written;
        WriteConsoleOutputCharacterA(console, &letters[i], 1, pos, &written);
        WriteConsoleOutputAttribute(console, &attribute, 1, pos, &written);
        oldLetters[i] = letters[i];
        oldColors[i] = colors[i];
    }
}
```

- **50:** получение дескриптора консоли перенесено из прежнего `draw`.
- **51:** сравниваются все клетки двух кадров.
- **52:** если и буква, и цвет прежние, `continue` пропускает клетку. Повторные вызовы `Line::show` поэтому не заставляют заново выводить неизменившиеся буквы.
- **53–55:** индекс обратно превращается в координаты. Остаток `i % width` даёт столбец, целая часть `i / width` — строку. `left` и `top`, как и раньше, учитывают положение видимого окна внутри консольного буфера.
- **56–57:** подготавливаются атрибут цвета и переменная для количества записанных элементов.
- **58:** прежняя функция Windows записывает один символ, но теперь берёт его из общего кадра.
- **59:** записывается цвет этой клетки.
- **60–61:** новое содержимое сохраняется как предыдущее для следующего сравнения.

Связь с `AppManager.cpp:126–130`: сначала собирается результат всех `Line::show`, затем он выводится целиком с учётом пересечений. Если символ исчез, в кадре окажется пробел или символ другой линии. Поэтому прежнее прямое стирание хвоста в `Line::step` больше не требуется.

### Новые часы — строки 65–67

```cpp
unsigned long long System::time() {
    return GetTickCount64();
}
```

Метод возвращает число миллисекунд с момента запуска Windows. Менеджер использует эти показания в `AppManager.cpp:99,102`: для начала секунды и текущего времени. Текущее время затем передаётся в `Line::step`. Так системный вызов остаётся в `System.cpp`, а остальные файлы работают с обычным числом.

### Изменённая пауза — строки 69–71

```cpp
void System::wait(int milliseconds) {
    Sleep(milliseconds);
}
```

Раньше было `Sleep(1000 / speed)`: пауза сама задавала скорость линии. Теперь `Sleep` получает готовую длительность в миллисекундах, а менеджер вызывает `wait(1)` один раз после обновления всех линий. Скорость перенесена в формулу `Line.cpp:16`, поэтому общая пауза больше не служит таймером отдельной линии. Фактическая длительность паузы зависит от планировщика Windows.
